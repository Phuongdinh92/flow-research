## Shared completion gates

1. **Identity:** every asset has chain+contract/native network or exact venue instrument/provider ID. Store mapping evidence and effective dates. Never join Q/BTW/other ambiguous tickers by name alone.
2. **Time and coverage:** record observation cutoff, provider event time, receipt time, requested/returned/valid counts and gaps. Define 1D/7D/30D rolling windows separately from completed calendar days/weeks/months.
3. **Reconciliation:** exact raw-unit balances and trades; deterministic deduplication; source hashes; aggregate-to-record replay. Zero is valid only when the source actually measured zero.
4. **Visual behavior:** token/chain/window switching, legends, zoom/pan/hover and empty states work; values and axes do not change meaning during switching. Reference screenshots validate shape/interaction, not today's numbers.
5. **Failure behavior:** preserve the last complete generation on errors; display its original age. Do not advertise collector success before an end-to-end run has been observed. A paid/rate/auth restriction is a source limitation, not a prompt to change routes to defeat it.
6. **Research validity:** a descriptive chart can ship when measured correctly. A predictive claim additionally needs predeclared rules, point-in-time universe/cohorts, costs, losing examples, untouched evaluation periods and comparison baselines. Current event study remains retrospective with survival bias.

### P2 — native valuation reference, then evidence-backed age cohorts

The existing independent reference is a valid starting point, not the unfinished four-band calculation hidden behind another name. Verify all 10 catalog entitlements and current source coverage during refresh, retain exact decimals, show supported assets before selection, and preserve daily USD price/Realized/EMA on the same axis.

[Coin Metrics capitalization documentation](https://gitbook-docs.coinmetrics.io/network-data/network-data-overview/market/market-capitalization) defines MVRV as market cap / realized cap and current market cap as price × current supply. Hence the implemented ratio recovers its native-network realized valuation per current unit. The provider's account-based last-debit treatment and private-supply adjustments differ from actual purchase cost. Its documented realized-cap age bands are currently Bitcoin-specific and do not cover ERC-20s.

Next feasible increment: inspect the source catalog for authorized Bitcoin age-band capitalization **and matching age-band supply** metrics. If both are available with compatible definitions, derive per-band valuation as band capitalization / band supply and label exact age ranges. Validate that bands reconcile to provider totals. If unavailable, show the missing dependency; do not substitute rank cohorts or constant multipliers. This is an independent age-cohort reference, not A1 Smart Bands. Exit: at least one fully reconciled asset; native-network and cohort scope visible. No promise to unlock all four proprietary A1 lines.

### P3 — complete a bounded on-chain inventory ledger before scaling

Start with one existing Ethereum token/pool and a declared finalized block interval. The current UNI/LINK/AAVE snapshot is 30 selected receipts, seven address/token positions and 30 state checkpoints per position; every position currently has unexplained movement. Complete all relevant Transfer events and pool swaps for the chosen interval through an authorized provider capability. Retain the current provider limitation until that capability is actually established. Do not claim a free-plan history limit is resolved merely because a smaller-looking request exists.

[Ethereum JSON-RPC](https://ethereum.org/developers/docs/apis/json-rpc/) defines range-filtered logs, receipts and block-specific calls; [ERC-20](https://eips.ethereum.org/EIPS/eip-20) defines `balanceOf`, supply and Transfer events. [Uniswap v3's event interface](https://github.com/Uniswap/v3-core/blob/main/contracts/interfaces/pool/IUniswapV3PoolEvents.sol) gives swap/LP event fields. These support independent reconstruction, not wallet ownership inference.

Implementation outputs: interval manifest with every block range accounted for; event IDs `(chain, blockHash, txHash, logIndex)`; before/after balances; swap routing to actual recipient; acquisition/disposal/transfer/mint/burn/unknown classes; residual by account. Reconcile `start + inflow − outflow = end` for supported conventional tokens. Treat fee/rebase/proxy upgrades separately. A zero residual is necessary but does not prove completeness by itself. Exit: complete scoped retrieval plus independent state reconciliation, before calling the result a complete ledger.

### P4 — holder cohorts and retention from that ledger

Extend `holder-history.js`'s fixed-anchor approach. HBAR already has 32 actual observations over a thresholded account universe; preserve exact source timestamps, not synthetic midnight states. [Hedera's mirror-node guidance](https://hedera.com/blog/querying-data-on-hedera-sdk-vs-mirror-node-rest-api/) explicitly describes balances as snapshots. TON top-N absence remains unknown until the missing account is read independently.

For an EVM holder population, bootstrap a verified starting state or reconstruct from deployment using a supported token model; incremental logs alone cannot discover all pre-existing holders. Define five rank cohorts at the older endpoint, store membership, report current-rank distribution separately, and explain rank entries/exits without claiming buys/sells. Add evidence-dated exchange/treasury/bridge/pool exclusions; unknown accounts remain unknown. A top-N sample may have a sample Gini, never a full-holder Gini. Retention needs complete subsequent transfers; units mixed in an account require disclosed lot assumptions/bounds. Exit: 1D/7D/30D cohort changes reconcile to their fixed members, with exact/bounded/missing outcomes distinguished.

### P5 — qualified cohorts, derived indicators and validation

Only after P3/P4, define an independent trader cohort using a pre-analysis training period, fee-inclusive realized outcomes, minimum history, and published exclusions. Freeze membership for evaluation; preserve cohort versions and handle entry/exit without hindsight. This supplies independently named netflow, status, capital and clustering features. Composite indices wait until all their required components exist. Evaluate early-accumulation hypotheses against matched controls and costs; price rising after a hand-picked signal is not a validation result.
